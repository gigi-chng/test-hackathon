# Content Agent — Evaluation Plan

**Status:** draft, pre-registered
**Owner:** Megan
**Decision this informs:** do we let the agent draft unsupervised, keep it human-gated, or rebuild it?

---

## 1. The question

> When the agent writes a post, would a partner actually publish it — at the same rate they'd publish something they wrote themselves?

Everything below is built to answer that one question and nothing else. Engagement,
time saved, and volume are explicitly out of scope for this round (see §9).

---

## 2. Design in one line

Generate a batch of agent drafts offline, shuffle them together with real posts the
partners actually published, strip every tell of which is which, and have reviewers
rate all of them on the same rubric.

**Primary metric:** % of items marked *"I would post this as-is"*
**Read:** the *gap* between the agent arm and the human arm — not the agent's raw score

Comparing against a human arm rather than a fixed threshold is what makes this
trustworthy. If a reviewer is harsh that day, both arms drop together and the gap
survives. A raw approval number on its own tells you as much about the reviewer's
mood as it does about the agent.

---

## 3. Success criteria — commit to these before looking at data

| Outcome | Gap vs human baseline | Decision |
| --- | --- | --- |
| **Ship** | within 10 pts | let it draft unsupervised into a review queue |
| **Iterate** | 10–25 pts behind | keep human-gated, fix the top failure mode, re-run |
| **Rebuild** | >25 pts behind | the approach is wrong, not the prompt |

Secondary gates, all must hold to "Ship":

- **Format compliance ≥ 95%** (auto-checked, §6) — a draft that breaks house format is a fail regardless of how good it reads
- **Zero fabrications** across the batch — any invented fact, quote, stat, or misattributed take is a hard stop that overrides the headline number
- **No partner scores worse than 20 pts below the batch average** — an agent that nails Sam and butchers Yoni isn't shippable

Writing these down now is the point. Deciding what counts as success after seeing
the numbers is how every eval talks itself into a pass.

---

## 4. Sample size

Two-proportion test, α = 0.05, power = 0.80, assuming ~80% of real published
partner posts clear the "would post as-is" bar:

| Gap to detect | Agent rate | Per arm | Total ratings |
| --- | --- | --- | --- |
| 30 pts | 50% | 36 | 72 |
| 25 pts | 55% | 51 | 102 |
| **20 pts** | **60%** | **78** | **157** |
| 15 pts | 65% | 135 | 270 |
| 10 pts | 70% | 290 | 581 |

**Run 80 per arm = 160 items.** That reliably detects a 20-point gap, which is the
resolution the decision table above actually needs. Chasing a 10-point gap costs
581 ratings and won't change what you do.

Balance the agent arm across partners — 20 each for Sam, Will, Yoni, Megan — so
§3's per-partner gate is computable.

---

## 5. Building the two arms

### Agent arm (80 drafts)

Backfill against historical trends rather than waiting on the live 3/week cap.

1. **Pin the prompt.** Disable feedback injection at `lib/actions/trends.ts:242` and
   `lib/actions/content-generator.ts:245` for the run. Both pull prior `feedback`
   rows into the prompt, so with it live, draft #80 is generated by a measurably
   different agent than draft #1 and the batch isn't one condition.
2. **Freeze the trend set.** Pull historical trend signals, sample 80 spanning at
   least 8 weeks so you're not testing one news cycle.
3. **Bypass `weeklyCapReached()`** for the backfill path only. Do not lift the live cap.
4. Write to a separate table or tag with `source: "eval"` so eval drafts never
   reach the real approval queue.

### Human arm (80 posts)

Pull from `PartnerContent where sourceType = 'tweet'`, matched to the same four
partners and roughly the same time window as the trend sample.

**Read this before interpreting results.** These are posts the partner chose to
write and chose to publish. They're pre-filtered by taste and survivorship. The
agent's drafts are raw output with no such filter. The comparison is deliberately
unfair to the agent — *agent first draft vs. human published final*.

That's the right bar anyway, because it's the bar that matters in production. Just
don't read a 15-point gap as "the agent writes 15% worse prose." It partly reflects
that humans get to not publish their bad ideas. If the agent lands within 10 points
of that, it's a genuinely strong result.

### Blinding — where this usually breaks

Agent drafts carry structural tells that leak the condition instantly. Normalize
every item in both arms to plain text before review:

- Merge `hook` + `body` into one field — the two-part split is an agent signature
- Strip `partnerCitation` entirely — human posts don't cite themselves
- Drop or match attachments (`videoId`, `quoteTweetId`) — if only agent items have
  a quote tweet, you've unblinded the whole batch
- Normalize whitespace, smart quotes, and trailing punctuation

Then **verify the blind holds**: have someone not otherwise involved try to label
50 shuffled items. If they beat ~60% accuracy, a tell survived — find it and re-run
normalization before collecting any real ratings.

## 6. Rubric

Reviewers see one item at a time, in randomized order, no partner name attached
beyond the voice itself.

**Primary (binary, this is the metric):**
> Would you post this as-is, right now, under this partner's name?  → Yes / No

**Diagnostics (only asked when primary = No — these tell you what to fix):**

| Dimension | Question | 1–5 |
| --- | --- | --- |
| Topic worth | Was this worth posting about at all? | |
| Voice | Does it sound like this partner? | |
| Substance | Does it say something, or just gesture at a take? | |
| Fixability | Could you make this postable in under 2 minutes? | |

Splitting **topic worth** from **voice** is the highest-value part of this rubric.
They're separate failure modes with separate fixes — bad topic selection means the
trend scorer is wrong, bad voice means the generation prompt is wrong. A single
blended quality score hides which one you have.

**Auto-checked before human review** (no reviewer time spent on mechanical fails):

- Twitter: under 260 chars · no question marks · declarative ending
- LinkedIn: 600–900 chars · one-line hook + body · no em dashes · no questions · no partner attribution

Report format compliance separately from the human metric. A draft can be perfectly
formatted and still be vapid, and you want to see those two failures apart.

### Reviewers

Two reviewers minimum, both familiar with the partners' actual writing. Have them
independently rate the **same 40-item overlap** and compute Cohen's κ.

- κ ≥ 0.6 → acceptable, proceed
- κ < 0.6 → the rubric is ambiguous. Fix the rubric before trusting any result; a
  noisy dependent variable will happily produce a confident-looking wrong answer.

---

## 7. Confounds and what we're doing about each

| Confound | Why it bites | Control |
| --- | --- | --- |
| Feedback loop mutates the agent mid-batch | `trends.ts:242` injects past feedback into prompts; the agent isn't one condition | Pin the prompt for the run (§5) |
| Structural tells unblind the reviewer | Hook/body split, citations, attachments | Normalize + verify blind at ≤60% (§5) |
| Survivorship in the human arm | Published finals vs. raw drafts | Not removable — stated and interpreted, not hidden (§5) |
| Topic mismatch between arms | Agent picks trends; humans picked their own topics | Match window and partner; the topic-worth sub-score isolates it |
| Reviewer drift over 160 items | Standards move as fatigue sets in | Randomize arm order; cap at ~50 items/session |
| Single news cycle | One weird week distorts everything | Sample trends across ≥8 weeks |
| Partner imbalance | Agent may be good at one voice only | 20 per partner + per-partner gate (§3) |

---

## 8. Analysis

1. Two-proportion z-test on primary approval, agent vs human. Report the **gap with
   a 95% CI**, not just a p-value — the CI is what tells you whether "within 10
   points" is actually established or just not ruled out.
2. Per-partner breakdown, same metric.
3. Format compliance rate, agent arm only.
4. Among primary = No: rank the diagnostic dimensions to find the dominant failure mode.
5. Cohen's κ on the overlap set, reported alongside everything else.

**Qualitative pass — do this, it's where the actionable findings live.** Read every
rejected draft and tag a free-text failure reason. Cluster them after. The headline
number tells you *whether* to ship; the rejection clusters tell you *what to fix*,
and they consistently surface things no rubric anticipated.

---

## 9. Explicitly out of scope

- **Engagement.** No publishing instrumentation exists. Adding it is worth doing, but
  it's a different experiment needing months of volume, and it can't gate this decision.
- **Time saved.** Worth measuring eventually; not what this round is powered for.
- **Volume/throughput.** The 3/week cap is a policy choice, not an agent capability.
